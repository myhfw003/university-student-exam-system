# 07 · 安全、防作弊与合规设计

> 关联：`01-requirements.md` §2.5、`03-domain-model.md`、`05-api.md`
> 本文包含**能力边界声明**：防作弊在本系统中是"可审计 + 可威慑"，不是绝对防护。任何对外宣传都不得夸大为"杜绝作弊"。

---

## 1. 安全目标

| 目标 | 具体含义 |
|---|---|
| 身份可信 | 只有通过认证的用户能访问系统；令牌可被即时吊销 |
| 权限最小 | 每个操作只授予必要的权限点；跨用户数据访问必须被拦截 |
| 数据不可篡改 | 已接受的答案、焦点事件、审计日志不可被修改或删除 |
| 时间不可欺 | 作答时长与交卷时刻以服务端为准 |
| 痕迹可追 | 关键操作留痕；异常行为可事后分析 |
| 隐私合规 | 采集最少的个人信息，敏感字段脱敏，保留期可控 |

## 2. 威胁模型（STRIDE 精简）

| 威胁 | 场景 | 缓解措施 |
|---|---|---|
| **Spoofing** | 冒用他人账号登录 | 密码 PBKDF2 + 锁定策略；令牌轮换 + 复用检测；登出/改密即时吊销 |
| **Spoofing** | 篡改 JWT 冒用他人身份 | RS256 签名 + `kid` 支持轮换；短时效 access token；服务端校验用户状态 |
| **Tampering** | 篡改请求体抬高分数 | 服务端权威判分；`ScoreResult` 只能由领域方法改写；改分留 `grade_revision` |
| **Tampering** | 越权改他人答卷 | 所有作答端点校验 `attempt.user_id == currentUser`；越权返回 404 而非 403（不泄露存在性） |
| **Tampering** | 直接改库提分 | 应用账号对 `app` / `audit` schema 无 UPDATE/DELETE 权限；数据库账号分离 |
| **Repudiation** | 声称未作弊 | 焦点事件、心跳、答案修订流水全部追加式留痕 |
| **Repudiation** | 教师私自改分 | 改分写入 `grade_revision` 与审计日志，学生端可见改分记录 |
| **Information disclosure** | 提前拿到答案 | 答题接口**不返回** `correctKeys`；考试进行中一律不给答案与解析，场次关闭后按 `answerPolicy` 公布；试卷快照要 `paper:write` 才能读（快照里冻结着答案）；读题库时答案与解析脱敏 |
| **Elevation of privilege** | 重置密码后带着初始密码继续用 | 管理员重置密码或导入名单时置「必须改密」；令牌带该标记，期间除改密、本人档案与登出外一律 403；改密成功换发新令牌 |
| **Information disclosure** | 看到他人成绩 | 学生端查询强制按 `user_id` 过滤；管理端需权限点且仅限所负责场次 |
| **Denial of service** | 疯狂刷保存接口打爆数据库 | 每用户限流；答案保存走原生批量 upsert；单批上限 50 条 |
| **Denial of service** | 1000 人同时开考 | 试卷快照缓存；会话创建限流；连接池与 PgBouncer 隔离 |
| **Elevation of privilege** | 学生给自己加管理员角色 | 角色变更端点需 `role:write`；`AuthorizationBehavior` 双层校验；审计留痕 |
| **Elevation of privilege** | 伪造请求体中的 `userId` | 当前用户从令牌解析，**从不信任请求体中的用户标识** |

## 3. 认证与会话安全

### 3.1 密码

- 哈希算法：PBKDF2-HMAC-SHA256，100,000 迭代，每用户独立盐。直接使用 ASP.NET Core Identity 的 `PasswordHasher<TUser>`（无额外第三方依赖，MIT）。
- 强度规则：长度 ≥ 8，且至少包含字母与数字；不得与登录账号相同、不得包含常见弱口令。
- 重哈希：登录成功时若算法参数升级，顺带重算并更新哈希。
- **永不记录明文密码到日志**：请求体中的 `password` 字段在 Serilog 中被脱敏。

### 3.2 令牌

| 项 | Access Token | Refresh Token |
|---|---|---|
| 载体 | JWT，存前端**内存** | 不透明随机串，存 `HttpOnly; Secure; SameSite=Strict` Cookie |
| 有效期 | 15 分钟 | 7 天 |
| 内容 | `sub`(userId), `role`, `perm[]`, `jti`, `iat`, `exp`, `iss`, `aud` | 仅哈希入库 |
| 吊销 | Redis 黑名单（`jti`，TTL = 剩余有效期） | `iam.refresh_token.revoked_at` |

- 签名算法 RS256（非对称，便于密钥轮换而无需重新分发对称密钥）。私钥由环境变量注入或挂载文件。
- 密钥轮换：`kid` 头 + JWKS 端点，允许同时持有新旧公钥。
- **刷新轮换 + 复用检测**：每次刷新签发新令牌、吊销旧令牌并记 `replaced_by_id`；若检测到已吊销令牌被再次使用，**吊销整个 `family_id` 令牌族**并强制重新登录，同时写审计日志。这是 Refresh Token 盗用检测的标准做法。

### 3.3 登录防护

- 连续 5 次失败锁定 15 分钟（`iam.user.failed_login_count` + `locked_until`）。
- 按 IP + 账号双维度限流。
- 登录失败提示统一为"账号或密码错误"，不区分账号是否存在。
- 所有登录尝试（成功与失败）写入 `iam.login_attempt`，用于异常检测。

### 3.4 登出与封禁

- 登出：吊销当前令牌族 + 将 access token 的 `jti` 加入黑名单。
- 管理员禁用用户：发布 `UserDisabled` 事件 → 吊销该用户全部令牌族 → 后续请求即时 401。
- 修改密码：吊销该用户**除当前会话外**的全部令牌族。

## 4. 授权

### 4.1 两层校验

```
第 1 层：Controller 上的 [Authorize(Policy = "paper:publish")]   ← 粗粒度，挡路由
第 2 层：MediatR 管道的 AuthorizationBehavior                      ← 细粒度，挡用例
```

任一层缺失都会导致测试失败（架构测试断言所有写 Command 都标注了权限需求）。

### 4.2 数据范围（水平越权防护）

权限点解决"能不能做这个操作"，数据范围解决"能操作谁的数据"。两者**必须同时校验**。

| 场景 | 规则 |
|---|---|
| 学生查自己的成绩 | `attempt.user_id == currentUserId`，不满足直接 404 |
| 学生读答卷 | 同上；**即使猜到别人的 attemptId 也拿不到** |
| 教师看成绩 | 需 `analytics:read` + 该教师是场次的负责人或题目作者 |
| 阅卷教师 | 只能看到分配给本人或本人已领取的任务 |
| 监考 | 只能监考被授权的场次 |
| 标签管理 | 组织维度标签的写入需 `tag:write`；给用户挂标签需 `user-tag:assign` |

实现约定：所有按 ID 查询的 Handler **必须**在查询条件中带上当前用户的范围约束，而不是查出来再判断。用**集成测试**逐条验证越权访问返回 404/403。

### 4.3 越权响应的选择

- 资源不存在与无权访问**都返回 404**，不泄露"该 ID 存在"这一信息。
- 403 只用于"资源确实属于你可见范围但缺少操作权限"的情况。

## 5. 传输与存储安全

| 层 | 措施 |
|---|---|
| 传输 | 全站 HTTPS（生产由 nginx 终结 TLS 1.2+/1.3）；HSTS `max-age=31536000; includeSubDomains`；HTTP 到 HTTPS 跳转 |
| Cookie | `Secure; HttpOnly; SameSite=Strict`；`__Host-` 前缀进一步约束 |
| 密码 | PBKDF2 哈希，不可逆 |
| 数据库口令 | 环境变量注入；不落 `appsettings.json`、不入仓 |
| 对象存储 | 私有桶；附件通过**短期签名 URL**（默认 5 分钟）访问；密钥仅用于签名，不直接暴露 |
| 备份 | `pgBackRest` 加密归档，密钥独立保管 |
| 日志 | 手机号脱敏（前 3 后 4）、令牌与密码全掩码、身份证号不入系统 |

### 5.1 密钥管理

| 环境 | 注入方式 |
|---|---|
| 本地开发 | `.env`（在 `.gitignore` 中）+ `dotnet user-secrets` |
| CI | CI Secret → 环境变量 |
| 生产 | Docker Compose 的 `env_file`（指向仓库外的 `.env`）或 K8s Secret |

**红线**：
- CI 扫描 `appsettings*.json` 与 `.env*`，命中 `password` / `secret` / `private_key` 的**值**即失败。
- `.env.example` 只含变量名与说明，不含真实值。
- 密钥轮换：JWT 签名密钥支持双密钥并存平滑轮换；数据库口令轮换需重启连接池。

## 6. 防作弊机制

### 6.1 能力边界声明（必须对外明示）

本系统的防作弊由五层构成，**全部基于客户端上报或服务端可观测行为**，没有任何一层能阻止有意规避客户端检测的行为：

| 层 | 手段 | 强度 |
|---|---|---|
| L1 时间 | 服务端权威计时，改本地时钟无效 | **强**（纯服务端） |
| L2 差异化 | 每人题序/选项顺序不同，抄也抄不准 | **中** |
| L3 行为 | 切屏、全屏退出、复制粘贴检测与计数 | **弱**（客户端上报，可被绕过） |
| L4 监考 | 教师实时可见并可警告/强制交卷 | **中**（依赖教师在场） |
| L5 追溯 | 答案修订流水、焦点事件、改分记录全部留痕 | **强**（事后追责） |

**因此**：系统承诺的是"作弊行为可被记录、可被威慑、可被事后认定"，不是"作弊不可能发生"。产品文案、用户手册、培训材料都不得使用"杜绝作弊""无法作弊"等表述。

### 6.2 L1 服务端权威计时

- `Attempt.DeadlineAt` 在会话创建时由服务端计算并入库，客户端**无法**修改。
- 保存答案接口校验 `now <= DeadlineAt`，超时拒绝。
- 交卷接口由服务端判定 `SubmitReason`（`manual` / `time_up` / `proctor_force` / `network_timeout`），客户端声明的 `reason` 仅作为参考。
- 多实例部署要求 NTP 同步，`ClockSkewMonitor` 每 30 秒上报偏移，> 50 ms 告警。

### 6.3 L2 差异化卷面

- 卷型 `standard` / `small_plum` / `large_plum`，置换种子由 `(sessionSeed, studentKey, questionId)` 确定性派生。
- 同一考生重进同一场次卷面一致（不因刷新而变卷）；不同考生卷面不同。
- 判断题固定"正确/错误"，不参与置换（避免"正确项位置"泄露难度）。

### 6.4 L3 行为检测

见 `06-frontend.md` §6。服务端侧要点：

- **计数以服务端为准**：`Attempt.FocusLossCount` 只增不减，客户端无法重置。
- **事件去重**：同类型事件在 500 ms 窗口内合并为一次（避免切标签页时 blur + visibilitychange 双计数）。去重在服务端做，客户端上报原始事件。
- **策略在服务端判定**：是否超限、超限后是警告还是强制交卷，由服务端按 `ExamRules` 决定并返回，前端只负责呈现。
- **心跳**：15 秒一次；45 秒无心跳判为断连（服务端判定，不信任客户端声明）。
- **强制交卷**：服务端把会话置为 `force_submitted`，该会话**立即拒绝**后续保存请求。

### 6.5 L4 监考与处置

- 实时大屏按 2 秒批量聚合推送。
- 处置动作（警告 / 备注 / 强制交卷）全部写 `delivery.proctor_action` 与审计日志。
- 强制交卷必须填写原因，原因对考生可见。

### 6.6 L5 追溯

| 数据 | 留存 | 用途 |
|---|---|---|
| `app.answer_revision` | 12 个月在线 + 归档 | 还原作答过程，证明作答时间线 |
| `app.focus_event` | 12 个月在线 + 归档 | 认定切屏行为 |
| `app.grade_revision` | 永久 | 认定改分过程 |
| `audit.audit_log` | 24 个月在线 + 归档 | 认定管理操作 |

### 6.7 练习模式

练习**不启用**切屏限制、不计时强制交卷、不做全屏要求。仅在教师显式开启"记录学习行为"时记录焦点事件用于分析，不作处置。

## 7. 输入安全

| 攻击面 | 防护 |
|---|---|
| SQL 注入 | EF Core 参数化查询；标签树用参数化递归 CTE；禁止字符串拼接 SQL（架构测试检查 `FromSqlRaw` 的使用） |
| XSS | 题干/解析等富文本用 Markdown 渲染 + `rehype-sanitize` 白名单净化（仅允许标题、列表、代码、表格、链接、图片）；React 默认转义 |
| CSV 注入（公式） | 导入解析时对以 `= + - @` 开头的单元格加前缀 `'`；导出 CSV 时对危险前缀同样转义 |
| XLSX 压缩炸弹 | 限制解压后大小（默认 50 MB）与最大行数（默认 5 万行） |
| 恶意文件 | 附件类型白名单（png/jpg/webp）+ 大小限制 10 MB + 内容嗅探校验（不信任扩展名） |
| 开放重定向 | 不实现外部跳转参数；附件下载走签名 URL 到自有域名 |
| 批量枚举 | 所有列表接口强制分页且 `size ≤ 200`；用户/题目等敏感列表对非管理角色不开放 |
| 拒绝服务 | 请求体大小上限（默认 2 MB，附件端点单独放宽）、请求超时、全局限流 |

## 8. 审计

### 8.1 记录方式

- **自动**：EF `SaveChanges` 拦截器捕获实体变更，生成"谁在何时改了哪个对象的哪些字段"的摘要，写入 `audit.audit_log`。
- **显式**：关键业务动作由 Application 层显式调用 `IAuditRecorder`（如"发布试卷"、"强制交卷"、"发布成绩"），补充业务语义摘要。

### 8.2 必审计动作清单

登录成功/失败、登出、密码修改、密码重置、角色变更、用户禁用、用户标签变更、标签创建/改名/删除、题目创建/修改/发布/停用/删除、题库变更、导入采纳、组卷生成、试卷发布/撤回/归档、场次发布/关闭/取消、名单变更、监考处置、阅卷评分、成绩发布、改分。

### 8.3 审计日志的不可篡改

- 应用账号对 `audit` schema 只有 `SELECT, INSERT`。
- 审计日志与应用日志**分库存储**或至少分 schema 且独立权限。
- 定期把审计日志导出到只读归档（每日），归档件带哈希链。

### 8.4 日志脱敏

Serilog 的 `Destructure` 策略 + 自定义 `SensitiveDataMasker`：

| 字段 | 处理 |
|---|---|
| `password` / `newPassword` / `oldPassword` | 全掩码 `***` |
| `token` / `accessToken` / `refreshToken` / `authorization` | 全掩码 |
| `phone` | 保留前 3 后 4 |
| `email` | 保留首字符与域名 |
| `idCard` | 不采集 |

## 9. 隐私与合规

### 9.1 采集范围

系统只采集：登录账号、姓名、密码哈希、可选邮箱与手机号、组织标签（可选）、作答内容、成绩、行为事件（切屏/心跳时间戳）。**不采集**身份证号、人脸、地理位置、摄像头画面。

### 9.2 敏感度分级

| 级别 | 数据 | 处理 |
|---|---|---|
| 高 | 作答原文、成绩、行为事件 | 加密存储（磁盘）、访问受权限控制、日志不落全文 |
| 中 | 姓名、登录账号、手机号、邮箱 | 展示脱敏、按需最小化 |
| 低 | 账号状态、登录时间 | 明文 |

### 9.3 数据主体权利

| 权利 | 实现 |
|---|---|
| 知情 | 首次登录展示考试须知与数据使用说明，需勾选同意 |
| 查阅 | 学生可查看自己的全部作答与成绩 |
| 更正 | 学生可提交个人信息更正申请，由管理员在用户管理中处理 |
| 删除/匿名化 | 主体提出请求时按本节执行；作答与成绩数据默认一直保留，不做期满匿名化（ADR-019） |
| 限制使用 | 账号禁用后不再参与新考试；历史数据按保留策略处理 |

### 9.4 保留期

**不设默认保留期**（ADR-019，2026-11-21 定）：**没有明确清理的数据一直保留，
删除一律软删除**。原先那张逐类保留期表（作答流水 12 个月在线、审计日志
24 个月在线、登录日志 6 个月删除……）已作废。

| 数据 | 保留 | 到期处理 |
|---|---|---|
| 作答流水（`app.*`） | 一直保留 | 无自动清理；清理须显式执行 |
| 成绩与评分 | 一直保留 | 同上 |
| 审计日志 | 一直保留 | 同上 |
| 登录日志 | 一直保留 | 同上 |
| 账号与个人信息 | 一直保留；主体提出删除请求时按 §9.3 明确删除 | 删除或匿名化（明确动作） |

「一直保留」怎么落地：追加式表在**数据库层**就没有应用账号的 DELETE 权限
（§11、ADR-015），应用侧删不掉；内容域（题目 / 标签 / 题库 / 试卷）走软删除
（`deleted_at` + 全局查询过滤器排除），后端不留硬删实体的口子。
