| 权限点 | 社会人士 |

| `question:read` / `tag:read` / `paper:read` | ✓（仅自己可见的） |
| `review:grade` / `proctor:monitor` / `question:write` / `user:write` | ✗ |

## 2. 功能需求

### 2.1 身份与权限（IAM）

**FR-IAM-01 账号登录**
所有用户以**账号 + 密码**认证。账号不限定为学号：在校学生可用学号，社会人士可自选账号，教师可用工号。
- 验收：账号规则为 4..32 位，允许字母、数字、下划线、点、中划线，大小写不敏感唯一。
- 验收：登录成功返回 Access Token（JWT）、有效期、用户档案（姓名、角色、所属组织标签，可为空）；密码错误统一返回 `401 / 账号或密码错误`，不区分账号是否存在（防用户名枚举）；连续 5 次失败锁定 15 分钟。
- 验收：账号状态为 `Disabled` 或 `Locked` 时拒绝登录并给出明确原因。

**FR-IAM-02 令牌刷新与登出**
- 验收：Refresh Token 存于 `HttpOnly; Secure; SameSite=Strict` Cookie；刷新时**轮换**（旧令牌立即吊销，返回新令牌）。
- 验收：检测到已吊销的 Refresh Token 被复用时，**吊销整个 Token Family**，强制该用户重新登录，并记录审计日志。
- 验收：登出后，旧 Access Token 在其剩余有效期内也被拒绝（Redis 黑名单生效）。

**FR-IAM-03 修改密码与重置**
- 验收：学生可自助修改密码，需校验原密码；管理员可重置任意用户密码并强制其下次登录修改。

**FR-IAM-04 组织归属用标签表达**
不建独立组织树。院系 / 专业 / 班级作为**组织维度标签**存在，在该维度内以父子关系成树（学院 → 专业 → 班级）。
- 验收：用户通过标签挂载归属（学生通常挂班级标签），查询"所属组织"时由标签树推导最深的组织标签，**不单独存字段**。
- 验收：组织标签支持任意层级嵌套；删除仍有子节点或已关联用户的标签时拒绝删除并说明原因。
- 验收：考试名单与练习开放范围均以**组织标签集合**表达，与组卷按标签筛选共用同一套标签机制。

**FR-IAM-05 人员名单批量导入**
教师上传 CSV（**账号**、姓名、院系、专业、班级、邮箱、角色、可选初始密码）。账号与姓名为必填；院系/专业/班级三列**可空**（为空即视为社会人士）。
- 验收：逐行校验，账号重复、必填缺失时**该行标红并跳过**，不阻断整批；导入结束返回成功数、失败数与失败明细。
- 验收：已存在的账号执行**更新**（姓名/班级变更）而非报错，且不重置其密码。
- 验收：CSV 中的院系 / 专业 / 班级若对应标签不存在，**自动创建**组织维度标签并按层级挂接（不因标签缺失而失败）；已存在则复用。
- 验收：角色列可省略，默认按"是否有班级"推断（有班级→在校学生，无班级→社会人士）；显式指定时以指定为准。
- 验收：CSV 中的院系 / 专业 / 班级若对应标签不存在，**自动创建**组织维度标签并按层级挂接（不因标签缺失而失败）；已存在则复用。
- 验收：已存在的账号执行**更新**（姓名/班级变更）而非报错，且不重置其密码。
- 验收：导入操作写入审计日志。

**FR-IAM-06 角色分配**
- 验收：管理员可为用户授予/撤销角色；变更即时生效（下次鉴权即反映，无需重新登录）。

**FR-IAM-07 审计日志**
- 验收：记录操作者、动作、目标对象、变更前后摘要、IP、UA、时间；日志为**追加式**，仅管理员可查，支持按操作者/动作/时间范围/对象过滤。

### 2.2 标签与题库（Catalog）

**FR-CAT-01 五维标签**
五个维度：领域、知识点、能力、难度、组织。
- 验收：标签归属且仅归属一个维度；同维度内可设父标签形成树（领域→知识点、能力→子能力、组织→专业→班级均支持）。
- 验收：**维度隔离**：题目只能挂领域 / 知识点 / 能力 / 难度四维；组织维度仅用于挂载用户。两者不可混挂。
- 验收：难度维度标签携带 `level`（1..5），由管理员显式设置，不由名称反推。
- 验收：标签删除时**级联解除**其与题目、试卷、练习的挂载关系；若该标签正被一个已发布的组卷方案引用，删除被拒绝并说明。
- 验收：标签的引用计数（题目数 / 试卷数 / 练习数）在标签管理页可见。

**FR-CAT-02 标签筛选语义**
- 验收：按标签筛选题目时，支持"包含子标签"开关，默认开启（选"高等数学"命中其下所有知识点）。
- 验收：多个标签之间为**任一命中（OR）**语义，与原型一致；同一维度内可切换为"全部命中（AND）"。

**FR-CAT-03 题目 CRUD**
支持五种题型：单选、多选、判断、简答、综合操作题。
- 验收：题型专属字段按类型校验：单选恰有一个正确选项；多选至少两个正确选项；判断固定为"正确/错误"两选项且不参与选项置换；简答至少一个评分要点（要点文本 + 关键词列表）；综合操作题至少一个评分步骤（步骤提示 + 分值 + 参考答案 + 关键词）。
- 验收：题号唯一；分值范围 1..40；题干必填。
- 验收：单选题与多选题在保存时**按选项键去重并过滤不存在于选项中的答案键**。

**FR-CAT-04 题目状态流转**
`draft → published → disabled`，且 `disabled → published` 可恢复。
- 验收：新建题目一律进入 `draft`，审核发布后方可组卷。
- 验收：已发布题目可被停用；已停用可恢复为已发布；仅 `draft` 可被物理删除（其余走软删除）。
- 验收：批量发布 / 批量停用 / 批量丢弃，批量结果逐条返回成功与失败原因。

**FR-CAT-05 题目附件**
- 验收：支持上传图片附件（png/jpg/webp，单文件 ≤ 10 MB），存入对象存储；题目删除时附件软删除。
- 验收：附件访问通过短期签名 URL，不暴露存储内部路径。

**FR-CAT-06 题库**
- 验收：题库是题目的集合，可附标签与说明；统计展示总数、已发布 / 草稿 / 已停用三态计数、客观题与主观题分值拆分。
- 验收：题库可批量加入 / 移除题目；被已发布试卷引用的题目从题库移除时**保留题目本身**（仅解除题库归属）。

**FR-CAT-07 试题批量导入**
- 验收：支持 `.csv`（UTF-8，含/不含 BOM）与 `.xlsx`（读取首个工作表）。
- 验收：导入分三步：上传并**列映射**（把文件列映射到"题干/题型/选项/答案/解析/知识点/分值"字段）→ **解析预览**（逐行展示，错误行标红并给出原因）→ **采纳为候选题**。
- 验收：解析产出的题目进入 `draft` 状态，`source = import`，关联导入批次号。
- 验收：题型列接受中英文标签（单选题/single/单选）；难度列接受"基础/中等/较难"或 1/2/3；选项列接受 `A. xxx|B. xxx` 或换行分隔的多行格式。
- 验收：导入批次可追溯（文件名、列映射、采纳数量、采纳人、采纳时间）。

**FR-CAT-08 题目搜索与分页**
- 验收：题目列表支持按题库、题型、状态、标签、难度、关键词（题号或题干）过滤；支持分页与排序（默认按更新时间倒序）。
- 验收：查询全部走服务端分页，不做前端全量过滤。

### 2.3 组卷（Authoring）

**FR-AUT-01 试卷与练习的统一模型**
- 验收：`Paper` 通过 `kind` 区分考试卷与练习卷；两者共享题目、配分、题序、标签等字段，差异项（开放范围、次数、反馈时机、错题回流）挂在各自的规则对象上。

**FR-AUT-02 组卷方案与标签规则自动抽题**
**这是本项目的核心差异化能力。**
- 验收：教师可创建组卷方案，配置：标签条件（多标签、是否含子标签）、难度配比（各难度题数）、题型配比（各题型题数）、目标总分、题序规则。
- 验收：系统按规则从题库中**确定性抽题**：同一方案 + 同一随机种子 + 同一题库状态下，重复生成得到**完全相同**的题集。
- 验收：抽题池只含 `published` 且符合全部标签与难度条件的题目。
- 验收：**池量不足时明确报错**，逐条列出"难度=较难 需要 5 题，仅找到 2 题"这类缺口，**不做静默降级**（不自动拿别的难度凑数）。
- 验收：生成结果写入组卷方案快照，含每道题的命中理由（命中了哪个标签条件），可供教师复核。
- 验收：抽题后的分值按方案的目标总分在各题型/难度配额内自动分配，余数按题序靠前优先。

**FR-AUT-03 手工微调**
- 验收：教师可在自动生成结果上逐题增删、调整分值、调整顺序；调整后方案标记为"已手工修改"，重新生成时**须二次确认并给出差异提示**（新增/移除/分值变化的题目清单）。

**FR-AUT-04 题序规则**
- 验收：两种题序规则可选：按题型分块（单选 → 多选 → 判断 → 简答 → 综合操作，同题型内按难度从易到难）；按选题顺序（保持教师指定顺序）。

**FR-AUT-05 卷型（差异化试卷）**
三种卷型：标准卷（题序与选项均固定，全员同卷）、小梅花（题序统一，选项逐人乱序）、大梅花（题型块内题序与选项均逐人乱序）。
- 验收：置换**基于考生身份确定性派生**（同一人重进同一场考试，卷面一致；不同人卷面不同）。
- 验收：判断题固定为"正确/错误"两选项，**不参与选项置换**。
- 验收：卷型种子由系统按场次 id 派生并存储，管理端可预览任意考生的实际卷面（含"选项已置换"标记）。

**FR-AUT-06 发布校验与快照**
发布前 8 项校验：至少一道题；所选题均已发布；总分等于各题分值之和；试卷内无重复题；主观题分值占比（**警告**，可覆盖并填写理由）；时长与题量匹配（题均 0.5–20 分钟且每分 0.3–3 分钟，可警告）；标签数 ≤ 5；考试名单非空。
- 验收：未通过的项列出**具体不通过原因**（不是"校验失败"），并可点击定位到对应题目。
- 验收：发布时生成**试卷快照**，冻结题目正文、选项顺序、正确答案、分值。发布后修改题目**不影响**已发布的快照。
- 验收：撤回发布后快照保留，重新发布生成新版本快照。

**FR-AUT-07 卷型模板**
- 验收：可将一份试卷保存为模板（含名称、适用类型、卷型、时长、分值配置、题位清单）；可套用模板生成新卷，套用时跳过已停用题目并明确提示。

### 2.4 考试组织与交付（Delivery）

**FR-DLV-01 考试场次**
- 验收：场次由已发布试卷创建，含名称、开始时间、结束时间、时长、卷型、名单、考生须知。
- 验收：状态机 `scheduled → in_progress → closed`，另有 `cancelled`；状态由时间窗与人工操作共同驱动，非法流转拒绝。

**FR-DLV-02 名单与可见性**
- 验收：名单支持三种纳入方式：① **组织标签**（按学院/专业/班级批量纳入）；② **指定考生**（逐个勾选用户，含社会人士）；③ **全员开放**（不限名单，所有已注册用户可见）。
- 验收：场次发布时按组织标签展开并**物化**为考生名单，名单变更不影响已生成的名单（除非显式重生成）。
- 验收：不在名单内且未开放全员的用户看不到该场次，也无法通过接口进入。

**FR-DLV-03 开考与入场**
- 验收：进入答题页时服务端校验：场次在有效时间窗内、考生在名单内、场次未取消、该考生未超过重考次数。
- 验收：服务端返回本次作答的**卷面快照**（含置换后的题序与选项顺序）、**服务端当前时间**、**本次作答的截止时间**。

**FR-DLV-04 服务端权威计时**
- 验收：截止时间由服务端计算并下发，客户端本地倒计时只是显示，**改系统时间不影响服务端判定**。
- 验收：客户端定期与服务端同步时钟偏移，偏移突变超过阈值时提示用户并以服务端时间为准。
- 验收：到达截止时间后，服务端**拒绝**该会话的继续作答请求；客户端倒计时归零时触发自动交卷。

**FR-DLV-05 答案自动保存与幂等**
- 验收：作答后**防抖批量**提交（默认 3 秒一批，或切换题目、页面隐藏、关闭前立即提交）。
- 验收：每批携带**单调递增的客户端序列号**，服务端据此去重，重复提交同一批不产生重复记录。
- 验收：保存成功的答案，**刷新页面、关闭浏览器、重启设备后重新进入都能恢复**。
- 验收：保存失败时向用户可见地提示"保存失败，正在重试"，且答案保留在本地不丢失。

**FR-DLV-06 离线与断网续传**
- 验收：断网时答案写入浏览器 IndexedDB 队列，界面显示离线状态与待同步条数。
- 验收：网络恢复后自动按序重放队列，并与服务端做序列号对账，保证不丢不重。
- 验收：即使整场考试全程断网，联网后交卷的数据与本地记录一致（以重放后的服务端数据为准）。

**FR-DLV-07 交卷**
- 验收：交卷前弹窗显示"已作答 N / M 题"与"未作答 N 题"，并说明未作答按 0 分计、主观题进入阅卷队列。
- 验收：交卷接口**幂等**，重复调用返回同一结果。
- 验收：交卷原因可区分：手动交卷 / 时间到自动交卷 / 教师强制交卷 / 断网超时由服务端代交。
- 验收：交卷后答案与评分结果不可再修改（阅卷教师改分走独立路径并留痕）。

**FR-DLV-08 重考与补考**
- 验收：场次可配置是否允许重考；重考时生成新的 `Attempt`（`attempt_no` 递增），旧尝试完整保留。
- 验收：成绩默认取最高分（可配置为取最后一次）。

**FR-DLV-09 练习模式**
- 验收：练习以"练习开放单"形式面向指定学生或全体开放；可配置可提交次数（0 = 不限）、解析反馈时机（每题作答后即时 / 提交后统一）、错题是否自动回流错题本。
- 验收：练习**不限制切屏、不计时强制交卷**；有建议时长但不倒计时。
- 验收：即时反馈模式下，作答后展示该题的正误判定与解析（仅练习，不涉及考试卷）。
- 验收：练习次数用尽时拒绝提交并提示。

### 2.5 防作弊与监考

**FR-ANT-01 切屏检测与计数**
- 验收：考试模式下监听窗口失焦、页面隐藏、全屏退出；每次上报服务端计数并记录明细（题位、时间、事件类型）。
- 验收：计数以**服务端**为准；客户端重放请求不能减少计数。
- 验收：第 1、2 次切屏弹窗警告；达到阈值（默认 3 次）按策略处置。

**FR-ANT-02 防作弊策略**
- 验收：每场考试可配置：切屏上限、超限处置（警告 / 强制交卷）、是否要求全屏、是否禁用复制粘贴、是否禁用右键菜单、是否叠加姓名与账号水印、是否启用心跳断连检测。
- 验收：策略变更只影响其生效时间之后的行为。

**FR-ANT-03 心跳与断连**
- 验收：作答期间客户端每 15 秒发送一次心跳；服务端记录最后心跳时间，超过 45 秒未收到判为断连并计入断连次数。

**FR-ANT-04 实时监考大屏**
- 验收：教师端打开场次监考视图后，实时看到每个考生的状态（未开始 / 作答中 / 已交卷 / 已强制交卷 / 断连中）、切屏次数、断连次数、最后心跳时间、已答题数。
- 验收：更新以**批量聚合**方式推送（默认 2 秒一批），不做逐事件即时推送。
- 验收：监考视图与 1000 并发作答**同源运行**，监考不得显著挤占作答接口的资源。

**FR-ANT-05 监考处置**
- 验收：教师可对单个考生：发送警告（考生端弹出提示）、添加备注、强制交卷。
- 验收：每次处置记录操作人、时间、原因，写入审计日志并在考生端可见（强制交卷需注明原因）。

**FR-ANT-06 防作弊强度声明**
- 验收：系统文档明确声明防作弊为"可审计 + 可威慑"，不宣称绝对防作弊（客户端检测可被篡改）。系统通过服务端权威计时、试卷差异化、答案追加流水、监考留痕共同降低舞弊空间。

### 2.6 评分与阅卷（Grading）

**FR-GRD-01 客观题自动评分**
- 验收：单选、判断题全对得满分，否则 0 分。
- 验收：多选题**错选不得分**；漏选按答对项占比折半计分（正确项 ABD，漏选 A 得该题分值的 1/4）。
- 验收：自动评分在交卷时立即完成并可见客观题得分。

**FR-GRD-02 主观题自动初判**
- 验收：简答题按评分要点的关键词命中数等分该题分值（每要点均分），产出**建议分**。
- 验收：综合操作题按步骤分别判定，按步骤分值加权产出建议分。
- 验收：初判结果标记为 `auto_suggested`，必须经人工确认才是最终分。

**FR-GRD-03 人工阅卷队列**
- 验收：交卷后，主观题自动生成阅卷任务，综合操作题**按步骤拆分为独立任务**。
- 验收：任务列表显示答题者、试卷、题目、步骤、提交时间、提交次序（重考时显示"第 N 次作答"）。
- 验收：教师可给分（0..满分，步进 0.5）、写评语（学生端可见）；可"采纳初判建议"批量确认。
- 验收：支持按试卷、题目、状态、阅卷人过滤；提供"上一份 / 下一份"连续阅卷。

**FR-GRD-04 阅卷分发**
- 验收：阅卷任务可指派给特定阅卷教师；未指派时由有 `review:grade` 权限的教师领取（先到先得）。

**FR-GRD-05 成绩发布**
- 验收：客观题得分在交卷后即可见，主观题待阅；教师可选择发布范围（全部 / 仅客观题已完成的）。
- 验收：发布动作后学生端成绩报告生效；发布前学生只能看到客观题分数与"待阅"标记。

**FR-GRD-06 成绩报告**
- 验收：学生可查看：客观题得分、主观题得分、总分、交卷时间、逐题明细（自己的作答、得分、正确答案、解析，按 `publishAnswer` 策略决定是否显示答案与解析）。
- 验收：答案公布策略三档：`immediately`（开考即公布）、`after_submit`（本人交卷后）、`after_close`（场次结束后）。

### 2.7 学习与分析（Learning / Analytics）

**FR-LRN-01 错题本**
- 验收：练习与考试中答错/部分正确的题自动回流为错题，记录错误次数、最后错误时间、错因（按题型归类）。
- 验收：学生可查看、筛选（按标签/题型/时间）、单题重做；重做正确后**移出错题本**（可配置为保留但标记已掌握）。

**FR-LRN-02 能力画像**
- 验收：按"能力"维度的标签聚合学生表现，给出掌握度（0..1）与样本量；样本量不足时明确标注"样本不足"。

**FR-LRN-03 成绩分析（教师端）**
- 验收：按场次输出平均分、最高/最低、及格率、优秀率、分数段分布、题型得分率、逐题正确率与掌握度。
- 验收：逐题正确率低于阈值时给出讲评建议。
- 验收：所有统计基于**真实作答数据**，不使用模拟数据。

**FR-LRN-04 学生工作台**
- 验收：工作台展示待完成练习、进行中考试、学期平均分、待订正错题数、成绩趋势、错题分布、推荐练习。

### 2.8 审计与合规

**FR-AUD-01 关键操作留痕**
- 验收：以下操作必记审计日志：登录成功/失败、用户与角色变更、用户标签变更、题目发布/停用/删除、试卷发布/撤回、场次发布/取消、强制交卷、成绩发布、成绩修改、数据导入、规则生成。

**FR-AUD-02 敏感数据脱敏**
- 验收：日志与 API 响应中，密码、令牌、身份证号、手机号全文等一律脱敏；手机号保留前 3 后 4。

**FR-AUD-03 数据保留与导出**
- 验收：成绩与作答数据默认保留 3 年，到期归档；管理员可导出单场次成绩 CSV。

## 3. 非功能需求

### 3.1 性能（NFR-PERF）

| 编号 | 指标 | 目标 |
|---|---|---|
| NFR-PERF-01 | 单场考试并发考生数 | 1000 人同时作答，稳定无错误 |
| NFR-PERF-02 | 答案保存接口 p95 延迟 | < 500 ms |
| NFR-PERF-03 | 答案保存接口 p99 延迟 | < 1500 ms |
| NFR-PERF-04 | 答案保存接口 HTTP 错误率 | < 0.1% |
| NFR-PERF-05 | **答案丢失率** | **0**（由对账作业验证） |
| NFR-PERF-06 | 首次加载答题页（1000 人同时进入） | p95 < 3 s |
| NFR-PERF-07 | 开考瞬间的会话创建吞吐 | ≥ 300 次/秒 |
| NFR-PERF-08 | 监考大屏状态刷新延迟 | < 3 s |
| NFR-PERF-09 | 页面首屏可交互时间（学生端，桌面 4G 模拟） | < 2.5 s |

**容量模型**：1000 名考生、平均每 8 秒保存一次答案 → 平均约 125 次/秒；交卷前 1 分钟的集中保存，峰值约 1000 次/秒。系统按**峰值 1000 RPS** 设计。

### 3.2 可用性与可靠性（NFR-AVL）

| 编号 | 指标 | 目标 |
|---|---|---|
| NFR-AVL-01 | 服务可用性 | ≥ 99.5%（不含计划维护） |
| NFR-AVL-02 | 单实例故障 | 不影响考试进行；API 多实例 + 会话状态外置（Redis/PG） |
| NFR-AVL-03 | PostgreSQL 故障 | 考试进行中不作答不可用；恢复后不丢已保存答案 |
| NFR-AVL-04 | Redis 故障 | 令牌刷新与缓存降级，但**已登录用户的作答不中断**（作答路径不依赖 Redis 强一致） |
| NFR-AVL-05 | 数据备份 | 每日全量 + WAL 归档，RPO ≤ 5 分钟，RTO ≤ 30 分钟 |
| NFR-AVL-06 | 对账作业 | 每日核对"客户端已确认保存的序列号"与"服务端已接收的序列号"，差异必须为 0，不一致则告警并生成修复任务 |

### 3.3 安全（NFR-SEC）

| 编号 | 要求 |
|---|---|
| NFR-SEC-01 | 密码使用 PBKDF2（ASP.NET Core Identity 默认实现，≥ 100,000 迭代）加盐哈希存储，不可逆 |
| NFR-SEC-02 | 全站 HTTPS；生产环境 HSTS + Secure Cookie |
| NFR-SEC-03 | 所有写接口具备 CSRF 防护（Cookie 认证场景）或使用 Bearer Token（无状态） |
| NFR-SEC-04 | 越权防护：所有查询按当前用户的数据范围过滤，禁止仅凭 ID 越权读取（水平越权必须被拦截） |
| NFR-SEC-05 | 输入校验：所有 Command 入参经 FluentValidation 校验；题干等富文本渲染前经白名单净化，防 XSS |
| NFR-SEC-06 | 密钥（数据库口令、JWT 签名密钥、对象存储密钥）一律由环境变量注入，禁止入库入仓；CI 扫描配置文件中的硬编码密钥 |
| NFR-SEC-07 | 限流：登录接口按 IP+账号限流；答案保存接口按用户限流（防客户端失控打爆数据库） |
| NFR-SEC-08 | 依赖扫描：CI 执行 `dotnet list package --vulnerable` 与前端 `npm audit`，高危漏洞阻断合并 |
| NFR-SEC-09 | 答题内容与成绩对学生严格隔离：学生只能读到自己的作答与成绩 |

### 3.4 可观测性（NFR-OBS）

| 编号 | 要求 |
|---|---|
| NFR-OBS-01 | 结构化日志（Serilog，JSON 格式），每条日志带 `TraceId`、`UserId`、`AttemptId`（如适用） |
| NFR-OBS-02 | 指标导出 Prometheus：请求量、延迟分位、错误率、数据库连接池占用、Redis 命中率、答卷保存 QPS、活跃会话数、SignalR 连接数 |
| NFR-OBS-03 | 分布式追踪 OpenTelemetry，关键链路（开考、保存、交卷、评分）可追踪 |
| NFR-OBS-04 | 健康检查：`/health/live`（存活）、`/health/ready`（依赖就绪，含 PG / Redis）、`/health/startup`（迁移完成） |
| NFR-OBS-05 | 结构化审计日志与运行日志分离存储，审计日志不可被应用账号修改或删除 |

### 3.5 可维护性（NFR-MNT）

| 编号 | 要求 |
|---|---|
| NFR-MNT-01 | 领域层不依赖任何第三方 NuGet 包（除 .NET BCL），由架构测试强制 |
| NFR-MNT-02 | 数据库变更全部走 EF Core 迁移，禁止手工改表；迁移脚本入库并可在空库一次跑通 |
| NFR-MNT-03 | 后端单元测试覆盖率 ≥ 80%（领域层 ≥ 90%）；集成测试覆盖全部 Command 与关键 Query |
| NFR-MNT-04 | 前端关键流程（答题、交卷、组卷）有组件测试与端到端测试 |
| NFR-MNT-05 | 中文错误提示与错误码分离：面向用户的文案与面向开发者的错误码一一对应 |
| NFR-MNT-06 | 所有数据库表带中文注释，所有公共 API 标注用途说明 |

## 4. 关键业务流程

### 4.1 考试全流程

```
教师：标签与题目维护 → 导入/录入 → 发布题目
  → 创建组卷方案（标签规则 + 难度/题型配比 + 目标总分）→ 自动抽题 → 手工微调
  → 发布校验（8 项）→ 生成试卷快照
  → 创建考试场次（时间窗 + 名单 + 防作弊策略 + 卷型）→ 发布

考生：登录 → 工作台看到"进行中的考试" → 点击进入
  → 服务端校验（时间窗/名单/次数）→ 创建 Attempt → 下发卷面快照 + 服务端时间 + 截止时间
  → 作答（3 秒批量保存，失败入 IndexedDB 队列重放）
  → 心跳（15 秒）→ 切屏事件上报
  → 交卷（手动 / 时间到 / 教师强制）→ 客观题自动评分 + 主观题生成阅卷任务
  → 教师阅卷 → 发布成绩 → 学生查看成绩报告
```

### 4.2 练习全流程

```
教师：维护练习（题目 + 配分 + 开放范围 + 次数 + 反馈时机 + 错题回流开关）→ 上架
考生：登录 → 练习中心筛选 → 进入练习 → 作答（无切屏限制、无倒计时）
  → 提交（次数校验）→ 即时反馈 or 提交后统一解析
  → 错题自动回流错题本 → 错题可单题重做
```

### 4.3 断网恢复全流程

```
作答中 → 检测到断网 → 本地提示离线 → 答案写入 IndexedDB 队列（带序列号）
  → 网络恢复 → 自动重放队列（按序批量提交）→ 服务端按序列号去重
  → 队列清空 → UI 显示"已同步"
  → 若期间刷新页面：从 IndexedDB 恢复答题状态与队列，续答不丢
```

## 5. 明确不做的事（非目标）

| 项 | 理由 |
|---|---|
| 浏览器内核级锁定 / 强杀进程 | 需浏览器扩展或客户端程序，超出 Web 交付形态（见假设 A-03） |
| 人脸识别、摄像头监考 | 涉及隐私合规与硬件依赖，另行立项 |
| 移动端作答 | 桌面端优先；移动端在考试模式明确不支持 |
| 主观题自动给最终分 | AI 初判只作建议，最终分必须人工确认 |
| 多租户 SaaS 化 | 本期单租户部署 |
| 实时协同编辑 | 与考试场景无关 |
| 试卷共享市场 / 跨校题库 | 本期仅本单位内共享 |
