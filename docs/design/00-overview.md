## 1. 这份文档集解决什么问题

`claude.md` 定义了业务方向与技术底线，`docs/ui-design/` 提供了一套纯前端的交互原型（学生端 / 管理端 / 门户，约 1.1 万行静态 JS）。两者之间存在一条必须先补齐的鸿沟：

**原型是"界面"，不是"系统"。** 它没有后端、没有认证、没有数据库、没有网络请求，防作弊能力为零，网络抖动丢答案的风险由浏览器承担，组卷只能手工逐题勾选。

本项目因此不能沿用"照着原型翻译成 React"的路径。真实工作量在原型未覆盖的部分：五维标签驱动的自动组卷、服务端权威计时、答案的可靠持久化、切屏防作弊与处置闭环、1000 人同时开考的容量设计、RBAC 与名单范围。

本文档集的目标是：在写第一行代码之前，把**领域模型、边界、数据结构、接口契约、并发与可靠性策略、前端架构、部署形态、任务顺序**全部定死，使得后续编码是"照图施工"而非"边写边想"。

## 2. 决策摘要

以下 8 项是本次开发的关键决策，均已与需求方确认。完整论证见对应章节。

### D-01 全新独立实现

**决策**：本仓库从零开始建设，不复制、不移植任何既有本地代码。

**理由**：需求的核心差异点（五维标签体系 + 标签规则组卷 + 考试/练习双模式）在既有实现中不存在，硬性移植会把旧领域模型的包袱一并带入，而其代码规模会淹没本次真正的设计工作。

**影响**：基础设施（编排、监控、压测脚本）需在本仓库重新编写，但可完全按本次需求裁剪。

### D-02 参考来源的边界

**决策**：架构模式仅参考 GitHub 上的公开项目，不参考任何本地项目。

**参考对象与结论**：

| 参考项目 | 借鉴了什么 | 明确不借鉴什么 |
|---|---|---|
| [TAO](https://github.com/tao-ce/tao-ce)（Open Assessment Platform，PHP，GPL） | 高利害交付（high-stakes delivery）的严格性模型：题目隔离与随机化、rubric 评分 + 人工阅卷路由、交付期锁定 | 其 QTI 标准适配、PHP 技术栈、多租户 SaaS 化设计 |
| [lsgwr/spring-boot-online-exam](https://github.com/lsgwr/spring-boot-online-exam)（约 1.7k star） | 功能模块划分（学生域 / 教师域 / 管理员域）与角色继承模型的现实性；CSV/XLSX 批量导入作为教师核心生产力的定位 | 其防作弊能力（仅有倒计时自动交卷）、单机 MySQL 部署、并发模型 |
| [OpenOLAT](https://github.com/OpenOLAT/OpenOLAT)（Java LMS） | "考试作为课程内活动"的活动建模思路 | 其独立组织树模型（本项目改用标签表达归属）、庞大的 LMS 范围 |

**结论**：开源生态中"高并发 + 强防作弊 + 自动组卷"三者兼具的项目基本不存在。GitHub 上流行的中文考试系统（1.7k star 量级）在这三项上均为空白。本项目的差异化正落在这里。

**数据库实例决策**：使用本仓库 `deploy/` 下的独立 `postgres:17-alpine` 容器。理由：本机系统 PostgreSQL 15 在运行但当前用户无角色（需凭据），且另有多个属于其他项目的 `exam-*` 容器。独立容器与其它项目完全隔离，可随项目交付。连接串全部走环境变量，生产可无缝切换到托管实例。

### D-04 认证授权

**决策**：JWT Access Token + Refresh Token 轮换 + Redis 黑名单；Refresh Token 存 HttpOnly/SameSite Cookie；RBAC 采用 Policy-Based 授权。

要点：
- Access Token 短时效（默认 15 分钟），仅存于前端内存（Zustand），不落 localStorage。
- Refresh Token 长时效（默认 7 天），轮换式刷新，每次刷新轮换并保留 Token Family；检测到旧令牌复用时立即吊销整个 Family（防重放）。
- 吊销名单存 Redis（`jti` 黑名单），登出、改密、被管理员禁用时立即生效。
- 服务端无状态，API 可水平扩展。

### D-05 前端工程形态

**决策**：`frontend/student` 与 `frontend/admin` 两个独立 SPA，加 `frontend/shared` 共享包；pnpm workspace 管理。

理由：学生端与管理端的权限边界、发布节奏、体积诉求完全不同，考试进行中必须保证学生端加载轻、启动快。门户页（`docs/ui-design/index.html`）作为两个 SPA 的轻量入口，不单独建应用。

### D-06 组卷方式

**决策**：**标签规则自动抽题 + 手工微调**。

教师设定组卷规则（标签条件、难度配比、题型配比、目标总分），系统按规则从题库确定性抽题生成卷面，生成结果落入"组卷方案（Blueprint）"快照并可解释、可复现；生成后教师仍可逐题增删改、调整分值。

这是 `claude.md`"对指定标签的题目进行组卷"的字面要求，也是本项目相对开源同类项目的核心差异点。

### D-07 内容生产实现范围

**决策**：CSV/XLSX 批量导入**真实实现**（纯 .NET 解析，无外部服务）；AI 生成题目**接入真实大模型**（OpenAI 兼容协议，供应商与模型可配置切换），生成的题走与导入**相同**的校验后落为草稿候选题。

导入链路完整：文件上传 → 编码/格式探测 → 列映射 → 逐行解析与校验 → 预览（标出错误行）→ 采纳为候选题（草稿态）→ 审核发布。

AI 生成链路（见 ADR-023）：选供应商与模型 → 出题要求（题型、难度、知识点）→ 模型产出 → 按导入规则逐题校验 → 通过的落为候选题（草稿态），未通过的逐条给出原因 → 候选题队列审核发布。API Key 只从环境变量来，不入库。

### D-08 监考能力

**决策**：建设**教师端实时监考大屏 + 处置动作**。

教师可实时看到考生状态（在线/已交卷/切屏次数/断连次数/心跳状态），可对单个考生发警告、记录备注、强制交卷。数据经 SignalR 推送（按考试分组，2 秒批量聚合，避免 1000 条独立消息）。

理由：切屏计数若只有系统自动处置而无教师可见性，则无法处理"人不在但电脑在"的场景，也无法支撑事后审计。

### D-09 身份与归属数据

**决策**：自建账号体系（**账号 + 密码**），**账号不限定为学号**：在校学生可用学号作为账号，社会人士可自选账号，教师可用工号。内置角色（系统管理员 / 内容管理员 / 出题教师 / 阅卷教师 / 在校学生 / 社会人士）。**不建独立的组织树**，院系、专业、班级全部用**标签**表达。

**标签维度扩展为五个**：

| 维度 | 英文标识 | 作用对象 | 允许层级 |
|---|---|---|---|
| 领域 | `domain` | 题目、试卷 | 是 |
| 知识点 | `knowledge_point` | 题目、试卷 | 是 |
| 能力 | `ability` | 题目、试卷、用户（能力画像） | 是 |
| 难度 | `difficulty` | 题目 | 否（level 1..5） |
| **组织** | `organization` | **用户**（院系 / 专业 / 班级） | **是** |

**组织维度标签的语义**：一个标签表示一个组织单元，层级为「学院 → 专业 → 班级」，同维度内以 `parent_id` 成树。例如 `计算机学院`（无父）→ `计算机科学与技术`（父=计算机学院）→ `计科 2301 班`（父=计算机科学与技术）。

**学生的归属**：用户通过 `user_tag` 关联表挂载组织维度标签（一个学生通常挂到班级标签，班级标签已隐含其上级）。用户的"所属组织"在查询时由标签树推导（取最深的组织标签），**不单独存字段**，避免不一致。

**考试名单范围**：从"指向组织节点"改为"指向组织维度标签集合"，与组卷按标签筛选使用同一套标签机制。

**为什么不用独立组织树**：

1. 标签机制已能表达层级，再建一棵平行树是重复建模，且两套层级会不一致（学生既在组织树上又在标签上）。
2. 统一后，"这个标签下有哪些人"和"这个标签下有哪些题"是同一类查询，权限、导入、筛选的代码路径一致。
3. 组织维度的标签不承担题目分类语义，混用风险通过"维度隔离"约束：题目只挂前三个维度，用户只挂组织维度。

**代价与应对**：组织维度的标签要支持"导入时自动创建"（教师上传学生名单时给出的院系/专业/班级若不存在则自动建），否则导入会被卡住。这与题目标签的"必须先定义"策略不同，需在实现上区分。

**社会人士支持**：系统不假定用户是在校学生。

| 关注点 | 规则 |
|---|---|
| 账号 | 登录名为通用账号，不要求数字或学号格式。学生可用学号，社会人士自选（如 `zhangsan`、`lilei_2024`） |
| 组织标签 | **可选**。社会人士不挂任何组织标签 |
| 纳入考试 | 社会人士无法被"按班级"批量纳入，只能通过**指定考生**逐个加入，或使用**全员开放** |
| 数据导入 | 名单 CSV 的院系/专业/班级三列**可空**，为空即视为社会人士 |
| 统计分组 | 按班级分组时，社会人士归入"未分班"分组 |
| 角色 | 社会人士对应 `general_user` 角色，权限与"在校学生"一致（可参加考试与练习、查看自己的成绩与错题），但不依赖组织归属 |

## 3. 统一语言（Ubiquitous Language）

代码、数据库、API、前端文案统一使用以下术语。**禁止**在代码中使用 `Manager`、`Helper`、`Util`、`Wrapper`、`Handler`（非 CQRS 语义）这类通用词。

| 术语 | 英文标识 | 定义 | 禁止的近义替代 |
|---|---|---|---|
| 用户 | `User` | 系统的登录主体，学生/教师/管理员/社会人士都是 User | 账号、Account |
| 账号 | `Username` | 登录名，全局唯一；学生可用学号，社会人士自选 | 用户名、Login |
| 角色 | `Role` | 一组权限的集合，可赋予用户 | 用户类型、UserType |
| 权限 | `Permission` | 形如 `模块:动作` 的原子授权点 | 菜单、资源 |
| 组织标签 | 组织维度 `Tag` | 院系/专业/班级的树形标签，同维度内成树 | 班级、名单组、Department、Organization |
| 标签 | `Tag` | 五维分类词条，归属某一个维度 | 分类、Category |
| 标签维度 | `TagGroup` | 领域 / 知识点 / 能力 / 难度 / 组织 五个维度 | 标签类型 |
| 题目 | `Question` | 题库中的可组卷内容单元 | 试题、Item（Item 特指卷面题位） |
| 题位 | `PaperItem` | 某道题在特定试卷中的实例，携带分值与排序 | 题目（易混） |
| 题库 | `QuestionBank` | 题目集合，用于筛选与管理 | 科目 |
| 试卷 | `Paper` | 试卷的内容定义，可为考试卷或练习卷 | 考试、Exam（易混） |
| 组卷方案 | `Blueprint` | 自动抽题的规则与结果快照 | 策略、模板 |
| 卷型模板 | `PaperTemplate` | 可复用的试卷样板 | 模板 |
| 试卷快照 | `PaperSnapshot` | 发布时冻结的卷面，含题目正文与答案 | 试卷副本 |
| 考试场次 | `ExamSession` | 一次具体的考试安排：试卷 + 时间窗 + 名单 | 考试、试卷（易混） |
| 练习 | `Practice` | `Paper` 中 kind=Practice 的那一类，以 Assignment 形式开放给学生 | 试卷 |
| 作答会话 | `Attempt` | 一个考生在一份试卷上的作答过程 | 答卷、Session |
| 作答答案 | `Answer` | 会话下某题位的当前作答值 | 提交、Response |
| 修订记录 | `AnswerRevision` | 每次被服务端接受的保存动作的追加式流水 | 历史 |
| 焦点事件 | `FocusEvent` | 切屏 / 全屏退出 / 复制尝试等行为事件 | 日志 |
| 监考动作 | `ProctorAction` | 教师对某会话发出的警告、备注、强制交卷 | 操作 |
| 评分结果 | `ScoreResult` | 某题位的得分与判定依据 | 分数 |
| 阅卷任务 | `ReviewTask` | 主观题的人工阅卷工单 | 卷宗、Review |
| 成绩发布 | `GradePublication` | 一次成绩对考生可见的发布动作 | 发布成绩 |
| 错题 | `Mistake` | 学生在错题本中的一条错题记录 | 错题本 |
| 能力画像 | `AbilityProfile` | 学生按能力标签维度聚合的掌握度 | 画像 |
| 审计日志 | `AuditLog` | 关键操作的追加式留痕 | 操作日志 |

**特别提示三组易混词**，代码评审将强制检查：

- `Paper`（试卷定义） / `ExamSession`（考试场次） / `Attempt`（个人作答）
- `Question`（题库题目） / `PaperItem`（卷面题位）
- `Paper`（试卷） / `Practice`（练习，是 Paper 的 kind 子类）

## 4. 原型与目标系统的差距

### 4.1 原型已有、后端需完整实现

标签五维分类（单表 + group 判别）、五种题型（单选/多选/判断/简答/综合操作）、题库与题目 CRUD、题目发布状态流转、试卷与练习双形态、每题独立配分、题序规则、卷型（标准/小梅花/大梅花）、多选折半计分、简答关键词初判、综合题分步评分、人工阅卷队列、成绩统计与逐题正确率、学生端工作台/练习中心/考试安排/错题本/成绩报告。

### 4.2 原型完全没有、必须从零新建

| 缺口 | 依据 | 归属阶段 |
|---|---|---|
| 认证、会话、RBAC | `claude.md` 明写 RBAC | P0/P1 |
| 组织维度标签与名单批量导入 | 决定考试可见范围 | P1 |
| 标签规则自动抽题引擎 | `claude.md` 明写"按标签组卷" | P3 |
| 试卷快照与发布冻结 | 防止考试中途改题 | P3 |
| 考试场次（时间窗、名单、状态机） | 原型的"试卷"直接充当考试，无场次概念 | P4 |
| 服务端权威计时 | 原型仅本地倒计时，改系统时间即绕过 | P4 |
| 答案服务端持久化与幂等保存 | 原型全靠 localStorage | P4 |
| 断网续传队列（IndexedDB） | `claude.md` 明写"防止网络抖动而丢失答题结果" | P4 |
| 切屏/全屏/复制检测与计数 | `claude.md` 明写"限制切屏次数等防作弊" | P5 |
| 实时监考大屏与处置 | 决策 D-08 | P5 |
| 阅卷教师角色与阅卷分发 | 原型只有单一管理员 | P6 |
| 成绩发布与可见性控制 | 原型无发布动作 | P6 |
| 错题本（原型有 UI，无真实回流） | — | P7 |
| 能力画像 | `claude.md` 提到能力标签 | P7 |
| 审计日志 | 生产级底线 | P1 |
| 1000 并发的容量与压测 | `claude.md` 明写 | P0/P9 |

### 4.3 原型中的建模缺陷，后端必须修正

| 编号 | 原型问题 | 修正方案 |
|---|---|---|
| D1 | 学生挂班级用**班级名字符串**（`className`），而考试范围存**班级 id**，靠内存遍历做 id→name 映射 | 统一为组织维度标签：用户挂标签，考试范围存标签 ID，双方都不存冗余名称 |
| D2 | `questionIds` 与 `items[{qid,score}]` **双份存同一关系**，靠 `setPaperItems` 强制同步 | 只保留 `paper_item` 一张表 |
| D3 | 题目默认分 `questions[].score` 与卷面配分 `items[].score` 双份 | 题目保留 `default_score`，卷面配分是唯一事实来源，判分只认 `paper_item.score` |
| D4 | `status` 与 `published` 布尔**冗余表达发布态**，可见性判断要同时查两者 | 只保留 `status` 枚举，删除布尔冗余字段 |
| D5 | 难度不是题目字段，而是"难度"维标签的 `level`，无难度标签时**默认回落为中等(2)** | 题目冗余列 `difficulty_tag_id`（NOT NULL），由应用层在题目写入时同步；筛选直接走该列，不再有静默默认值 |
| D6 | 领域与知识点**只有命名约定，无父子结构** | 标签增加 `parent_id`，同维度内成树；按标签组卷时可选"包含子标签"（默认包含） |
| D7 | 3 个标签 id（`t-dom-math` / `t-pt-calc` / `t-pt-tree`）被引用但**未定义**，`validateTags` 判为无效 | 迁移时补齐定义或修正引用；引入数据库外键约束，杜绝悬空引用 |
| D8 | 发布前校验把"主观题占比 ≤ 40%"作为**硬阻断** | 降级为**警告**（可覆盖并记录理由）。这是业务建议而非数据完整性约束，硬阻断会卡住合法组卷 |
| D9 | 练习的 `archived`（已下架）状态**无任何写入路径** | 补齐 `published → archived` 迁移，纳入状态机 |
| D10 | `publishAnswer`（答案公布时机）字段存在但**答题端从未读取** | 真正实现三种策略：开考即公布 / 交卷后公布 / 考试结束后公布 |
| D11 | 阅卷记录 `status` 可写入任意字符串，**无受控流转** | 定义状态机 `pending → in_review → reviewed`，非法流转抛领域异常 |
| D12 | 难度标签 `level` 靠**名称反推**（`DIFFICULTY_LEVEL_MAP`），新增难度维度只能有 3 级 | 难度维度的 level 由管理员在标签编辑时显式设置，范围 1..5 |
| D13 | "名单组"是硬编码的 `EX.seed.classes` | 落库为组织维度标签（`group_name='organization'`），教师可维护、可导入、可在导入时自动创建 |
