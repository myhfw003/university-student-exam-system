# ADR-003：考试与练习共用 Paper 聚合，用 kind 区分

**状态**：已接受　**日期**：2026-11-12

## 背景

考试卷与练习卷在业务上高度相似：都有题目、都有分值、都有规则（时长、及格线、次数）、
都要被「某个人在某段时间做一遍」。如果分成两个聚合，两套题目装载、���套组卷规则、
两套快照逻辑都要各写一遍，日后加一个「模拟考」之类的形态就得再复制一遍。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 考试卷与练习卷两个聚合 | 各自演进，互不干扰 | 规则、装载、组卷、快照逻辑全部重写一遍 |
| 通用「卷」聚合，用 kind 区分 | 一套规则与装载逻辑 | 需要把两类差异收敛进 kind 分支 |
| 试卷与练习分表但共用领域模型 | —— | 领域模型统一而存储分裂，反而更难懂 |

## 决策

统一为 `Paper` 聚合，用 `kind`（`exam` / `practice`）区分：

- `Paper.Kind` 决定用哪套规则：`ExamRules`（考试：切屏上限、心跳、提前入场）或
  `PracticeRules`（练习：次数、即时反馈、是否计分）。
- 两套规则各占一列，数据库用 `ck_paper_rules_exclusive` 约束「只能有一边非空」——
  kind 与规则的不一致在数据库层就被挡住。
- 题目装载、组卷、快照、统计全部只做一套。

## 代价与后果

- 读代码时必须先看 kind 再看规则分支：两套规则差异大的地方容易看串。
- 约束 `ck_paper_rules_exclusive` 是新增的迁移，导入既有数据时要注意 kind 与规则的匹配。
- 收益：新增一种卷型（模考、周测）通常只是加一套规则 + 一个 kind 取值，不必复制整套流程。
