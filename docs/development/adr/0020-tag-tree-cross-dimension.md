# ADR-020：标签树允许内容维度之间跨维度挂接

**状态**：已接受　**日期**：2026-11-23

## 背景

需求 FR-CAT-02 的验收例子是「选『高等数学』命中其下所有知识点」。
按契约里的标签目录示例（`docs/design/05-api.md`），「高等数学」是**领域**标签——
它下面挂的是**知识点**标签。这要求**内容维度之间能成树（跨维度）**。

而初版设计（ADR-008、数据模型 §3.1）把标签树定成**维度内**的树：
`Tag.SetParent` 强制「父标签必须与当前标签属于同一维度」。
两边对不上：需求的验收例子在实现里根本建不出来——不是筛不准，
是那棵标签树压根建不出来。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 保持维度内成树 | 维度边界清晰；「同一维度内全部命中」的语义简单 | 需求的验收例子做不到——「高等数学」挂不了知识点 |
| **内容维度之间可跨维度成树** | 满足 FR-CAT-02；「包含子标签」天然跨维度 | 一棵树里混着几个维度，界面要按维度分组展示、按层级找父 |
| 全部维度都可跨维度（含难度、组织） | 规则最简单 | 难度是平铺的（难度等级就是它的层级）；组织维度只作用于用户，混进去会把题目标签与用户归属搅在一起 |

## 决策

**内容维度（领域 / 知识点 / 能力）之间可以成树；难度平铺、组织自成一体。**

- 规则收在**领域层**：`TagGroups.CanNest` / `EnsureCanNest`。
  三处校验（建标签、改标签、`Tag.SetParent`）都走它，说法一致。
- 难度维度仍是平铺的：难度等级（1..5）就是它的层级，再给一层树是多余的。
- 组织维度只作用于用户（FR-CAT-01 的维度隔离）：只挂组织维度的父，
  也不当内容标签的父。
- 后代展开（递归 CTE）本来就不带维度条件，跨维度自动生效；
  「包含子标签」筛选因此能命中另一个维度的后代。

## 代价与后果

- **标签树不再单一维度**：管理端按维度分组展示，同一个父标签下可能挂着
  别的维度的子标签；父标签下拉给的是**内容维度**里的标签（难度与组织不给）。
- **「全部命中」的范围变宽**：FR-CAT-02 说「同一维度内可切换为全部命中」，
  跨维度之后按「选中的每个标签（含其后代）都要被命中」理解。
- 前后端的维度词表要对齐：新增 CI 校验
  `scripts/check-tag-dimensions.py`（维度集合 + 内容维度集合两边比）。
- ADR-008 的「维度内的树」由本 ADR 细化，单表多维度这个核心决策不变。
