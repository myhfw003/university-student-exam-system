# ADR-024：AI 生成试题走 SSE 流式，题目一道道落库

**状态**：已接受　**日期**：2026-11-26

## 背景

ADR-023 定了「AI 产出走真实模型、校验与导入共用一套规则」。那条路做完就发现一个问题：
**模型出题很慢**。实测 MiniMax-M2.7 出 8 道题要 25 秒，M3 要 60 秒。

一次性返回的接口在这个时长下体验很差：

- 界面只能显示一个转圈，60 秒里老师不知道系统在干什么；
- 中途出错（限流、网络断、模型抽风）就整批白等——已经出好的题也看不到；
- 「请求超时」是当时的真实故障：前端 15 秒超时、服务端 300 秒超时，
  两头对不上，界面每次都报超时，而服务端其实早把题出好了。

还有一个容易被忽略的点：模型的输出是**增量到达**的。
一道题拼完就该落库，不该等到最后一整段 JSON 到齐才一起处理。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 一次性返回，把前端超时调大 | 改动最小 | 60 秒黑箱；中途失败整批丢失；「在生成」的可见性还是没有 |
| WebSocket 双向通道 | 能推也能收 | 生成是单向的；握手与鉴权比 SSE 复杂；断线重连对「一次性任务」没有意义 |
| **SSE（`POST` + `text/event-stream`）** | 单向、基于 HTTP、自带重连语义；浏览器原生 `EventSource` 之外，用 `fetch` 读流也简单 | 需要反向代理关缓冲；只能服务端推 |
| 轮询任务状态 | 基础设施现成 | 每次轮询都要带任务 ID 与状态存储，题目一道道出现的延迟取决于轮询间隔 |

## 决策

**走 SSE**：`POST /api/v1/ai/generations/stream`，服务端每落一道题就推一条事件。

1. **落库先于事件**。题目先写进候选题队列，**再**推 `question` 事件。
   顺序反了的话，界面上会出现「已生成」但刷新就没了的题——那是骗人的。
2. **三个事件 + 一个错误事件**：`question`（落库成功）、`failed`（没通过校验，
   不落库但要说明原因）、`done`（整批结束，带计数）、`error`（生成过程出错）。
3. **流开始后改不了 HTTP 状态码**（响应头早已发出）。所以出错推 `error` 事件，
   而不是改状态码；错误码仍用稳定契约（`27102` 等），前端照旧归一化。
4. **校验与一次性接口共用同一份规则**（`AiGenerationRequestRules`）。
   两个入口对同一个请求必须给出同一个结论——规则各写一套必然漂移。
   流式端点绕过了 MediatR 管道，所以校验要显式做。
5. **审计自己落库**。流式端点不走工作单元管道，没人替它提交；
   不显式提交，「谁在什么时候生成了题」这条记录就丢了。
6. **前端用空闲超时而不是总超时**：整批可能要一分多钟，
   但只要还在吐字就不算卡住（`AI_GENERATION_IDLE_TIMEOUT_MS = 120s`）。
7. **流式与非流式认模型输出的方式必须一致**。模型吐什么形状并不固定：
   直接给数组、包成 `{"questions":[…]}`、前面先来一段说明或思考段。
   两条路各写一套找法，必然一边认得一边不认得——2026-11-26 公测机实测：
   思考段里带一个方括号，流式那条路就把整个包装对象当成了一道题，
   界面只报「第 1 题缺少题干」，题一道都没出来。
   现在两边共用 `AiJsonPayload`：认的是「后面紧跟对象」的左方括号 `[{`，
   不是裸的 `[`。

## 代价与后果

- **部署上多一个要求**：反向代理必须关掉响应缓冲
  （nginx：`proxy_buffering off`），且读超时给够（300 秒）。
  漏了 `proxy_buffering off`，事件会被攒着一起到——接口是对的，可见性没了。
  这是最容易踩且最难一眼看出来的坑。
- **SSE 载荷是手写序列化的**：默认 `JsonSerializer` 是 PascalCase，
  而普通接口走 ASP.NET Core（camelCase）。不显式指定就会出现
  「事件收到了但字段全是空的」——所以控制器里固定用 `JsonSerializerDefaults.Web`。
- **客户端不能用 `httpClient`**：它会把响应体一次性读完，流就没了。
  流式接口直接用 `fetch` + `ReadableStream`，代价是 401 刷新那套逻辑要自己接。
- 收益：老师能看着题目一道道进候选题队列，中途出错也知道出到哪一道，
  而不是对着一个转圈等一分钟然后收到一句「请求超时」。
