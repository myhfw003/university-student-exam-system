# ADR-008：标签采用单表 + 维度判别 + 可选父标签树

**状态**：已接受　**日期**：2026-11-12

## 背景

系统里有多种「归类」：知识点、能力维度、难度、题型、学科、班级组织。
它们结构相似（都有名字、都要挂到题目 / 用户 / 场次上）但语义不同。
若每种维度各建一张表，加一种维度就要改 schema、加一套仓储、加一套接口。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 每种维度一张表 | 语义最纯 | 加维度成本高，接口与前端全要跟着改 |
| **单表 + 维度判别列** | 加维度只加枚举值 | 查询要带维度条件 |
| 通用 EAV（键值对） | 极灵活 | 无法约束、无法索引、统计要全表扫 |

## 决策

`iam.tag` 单表：

- `dimension` 判别列标明这是哪一维（知识、能力、难度、组织……）。
- 可选的 `parent_id` 形成维度内的树（如「数学 → 高等数学 → 线性代数」）。
- 标签是软删除的；被引用中的标签不可删（返回 `TagReferenced`）。

前端与 API 都按「维度分组返回全部标签」的方式消费（`GET /api/v1/tags`），
新增维度不需要改接口。

## 代价与后果

- 跨维度的查询要带 `dimension` 条件，漏写就会混。
- 维度内的树用 `parent_id` 表达，环检测靠领域层（`TagCycleDetected`）。
- 后续 ADR-018 用标签维度替代了独立的组织树，这张表同时承担了「组织」的职责。
