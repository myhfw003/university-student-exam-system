# ADR-010：试题导入走真实实现，不预留空的 AI 生成接口

**状态**：已接受（其中「不预留空的 AI 生成接口」一条由 [ADR-023](0023-ai-generation-real-model.md) 取代）　**日期**：2026-11-12

## 背景

老师的题库大多在 Excel / Word 里，不是一条条录进来的，所以「批量导入」是刚需。
同时产品设想里提到过「AI 出题」，但那条路当时既没有模型也没有确定的供应商，
更没有验收标准。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 只支持单条录入 | 实现最简单 | 老师的实际工作量不可接受 |
| **导入走真实实现：解析 → 列映射 → 逐行校验 → 采纳为草稿** | 老师的工作流真实可用 | 需要处理各种脏表格 |
| 导入时顺带做「AI 补全 / AI 出题」 | 想象空间大 | 没有模型、没有供应商、无法验收 |
| 先留一个空的 AI Provider 接口 | 看起来有扩展性 | 空接口没人实现，也没定义清楚要解决什么问题 |

## 决策

导入是**真实实现**，不是占位：

- 支持 CSV 与 XLSX 两种文件（按扩展名判定）。
- 解析后给出**列映射建议**（自动识别表头），老师可以调整映射后重新解析。
- 逐行校验：格式、题型、选项、答案是否合法，每行单独给结果，**单行出错只跳过该行**，
  不影响其他行。
- 采纳后落为**草稿题目**，仍要走发布流程才生效。

**不预留空的 AI 生成接口。** 理由：留一个没有实现、没有语义、没有验收标准的接口，
只是让后来的人以为「AI 出题已经支持了」。真要做时，按当时的模型能力与供应商重新评估，
比留一个空壳诚实。

## 代价与后果

- 脏表格（合并单元格、一列多题型、答案写"对/错"）无法 100% 自动识别，
  列映射与逐行纠正是必须的人工环节——这是刻意的：宁可让老师改一行，
  也不要系统猜错一行。
- 没有 AI 出题能力，产品层面要明确说明「不支持」，不能含糊。
- 收益：导入这条链路真的能用，不是一个演示。
