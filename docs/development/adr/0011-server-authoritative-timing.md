# ADR-011：服务端权威计时，客户端时钟仅作显示

**状态**：已接受　**日期**：2026-11-12

## 背景

考试有时间限制。「谁说了算」这件事上，客户端时钟是不可信的：考生改系统时间、
浏览器时区不对、机器时钟漂移，都会让「剩余时间」显示得离谱。更严重的是，
如果服务端也采信客户端提交的时间戳，考生就能通过改钟延长时间。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 客户端计时 | 零服务端成本 | 可被篡改；断线后无法判定 |
| 服务端按客户端上报的时间戳判定 | 看似省事 | 等于把判定权交给考生 |
| **服务端权威计时，客户端时钟只用于显示** | 判定不可篡改 | 客户端要处理时钟偏移 |

## 决策

- 剩余时间、截止判定、交卷原因（`time_up` 还是 `manual`）**一律以服务端时钟为准**。
  服务端在 `attempt.deadline_at` 上写死截止时刻，后续不再受任何客户端输入影响。
- 客户端可以调 `GET /api/v1/system/time` 采样服务端时间，用于**显示**上的校准
  （倒计时不跳秒、不因本机时钟不准而错乱）。时钟偏移本身也是一项监控指标
  （`clock_offset_ms`，见《08-deployment-operations.md》§5.1）。
- 交卷原因由服务端判定：客户端说什么不算数，客户端传「超时了」也不影响服务端记 `time_up`。

## 代价与后果

- 客户端多一次校准调用与一点偏移计算（`frontend/student/src/lib/serverTimeSource.ts`）。
- 心跳与断线判定用服务端时钟，避免「考生把时钟调回去就永远不算断线」。
- 代价可接受：显示精度与服务端一致，而判定权始终在服务端。
