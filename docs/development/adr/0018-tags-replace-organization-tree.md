# ADR-018：用标签维度替代独立组织树

**状态**：已接受　**日期**：2026-11-12

## 背景

初版设计为院系 / 专业 / 班级建了独立的**组织树**（`iam.organization` 表 + 物化路径 + 层级类型）。
需求方明确要求：**不搞组织树，使用标签来组织学生、专业甚至院系**。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 独立组织树 + 标签体系并行 | 组织语义独立、约束清晰 | **两套层级**，学生同时挂在两处，必然出现不一致；查询路径与权限模型重复 |
| 单一标签表，维度判别，组织作为第五个维度 | 一套机制表达所有归属；与组卷筛选共用查询路径 | 题目分类标签与人员归属标签混在同一张表，需要靠维度隔离约束 |

## 决策

标签表增加第五个维度 `organization`：

- 院系 / 专业 / 班级表达为组织维度标签，在该维度内以 `parent_id` 成树。
- 用户的归属通过 `iam.user_tag` 关联表挂载，**不单独存字段**；查询「所属组织」时由标签树上溯推导。
- 考试名单与练习开放范围存储**组织标签 ID 集合**，不再存组织节点 ID。
- **维度隔离约束**：题目只能挂领域 / 知识点 / 能力 / 难度四维；组织维度只用于挂载用户。
- 组织维度标签支持「导入时自动创建」（学生名单 CSV 里的院系/专业/班级若不存在则自动建并按层级挂接），
  这与题目标签「必须先定义」的策略不同，实现上以维度区分。

## 后果

- 删除了 `iam.organization` 表、组织层级类型枚举与物化路径维护逻辑。
- 社会人士支持变得自然：组织标签对用户**可选**，社会人士不挂任何标签，
  只能通过「指定考生」或「全员开放」参与考试。
- 代价是标签表同时承载两类语义，需要靠领域层校验（`User.AssignTags` 只接受组织维度标签）守住隔离。
