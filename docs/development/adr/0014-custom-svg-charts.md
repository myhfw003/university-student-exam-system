# ADR-014：图表自研 SVG 组件，不引入重型图表库

**状态**：已接受　**日期**：2026-11-12

## 背景

管理端要看成绩分布、分数段趋势、逐题正确率、能力雷达。图表库（ECharts、Chart.js）
体积在几百 KB 到数 MB 之间，引入后会带来授权核对、构建体积与主题适配三笔成本，
而本系统需要的图表种类其实很少。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| ECharts / Chart.js | 图表类型齐全，交互成熟 | 体积大；授权需核对；暗色主题要额外适配 |
| 轻量图表库（如 Chart.js） | 体积小一些 | 仍要引入依赖与授权核对 |
| **自研 SVG 组件** | 零依赖、样式与设计令牌一致、体积可忽略 | 只覆盖需要的图表类型；交互要自己写 |

## 决策

图表用原生 SVG 组件实现（`frontend/shared`），样式走设计令牌（CSS 变量），
暗色主题自动跟随。

只实现真正要用的几种：柱状、折线、环形、雷达、水平条。复杂交互（缩放、拖拽、联动）
不做——监考与统计场景都不需要。

## 代价与后果

- 新增一种图表要自己写，初期比引库慢。
- 收益：前端首屏体积不因图表变大；不引入新的授权核对项；图表与设计令牌完全一致，
  不会出现「图表库的主题和我们的主题对不上」。
