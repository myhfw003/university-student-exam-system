# ADR-016：密码哈希用 PBKDF2-HMAC-SHA256，自带版本化格式

**状态**：已接受　**日期**：2026-11-12

## 背景

用户表里存的是密码哈希。哈希算法选错，泄露一次就全量沦陷；同时算法参数要能升级
（迭代次数会随硬件变强而提高），但已存的哈希不能因此失效。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 明文 / 可逆加密 | —— | ❌ 不可接受 |
| MD5 / SHA-1 | 实现简单 | ❌ 已被攻破，不适合密码 |
| BCrypt / Argon2 | 参数现代 | 需引入第三方包（授权需核对）；.NET 内置没有 |
| **PBKDF2-HMAC-SHA256（.NET 内置 `Rfc2898DeriveBytes`）** | 零依赖；标准算法；参数可升级 | 参数升级时旧哈希要能验证 |

## 决策

用 .NET 内置的 `Rfc2898DeriveBytes.Pbkdf2`（HMAC-SHA256），**不引入第三方密码库**，
哈希串自带版本化格式：

```
$pbkdf2-sha256$<iterations>$<salt>$<hash>
```

- 默认 100000 次迭代、16 字节随机盐、32 字节哈希。
- 验证时从哈希串里读回迭代次数，因此**参数升级后旧哈希仍然可验证**。
- 迭代次数低于当前标准时，验证返回 `SuccessRehashNeeded`，登录成功后顺带重算并回写。
- 比较用 `CryptographicOperations.FixedTimeEquals`，不做短路比较。
- 批量导入用户时生成一次性随机初始密码（去掉了易混淆字符），并要求首次登录修改。

## 代价与后果

- 自实现意味着参数与格式要自己维护：好处是格式可读、可升级，坏处是没有社区兜底。
- 100000 次迭代在登录路径上有真实开销（几十毫秒量级），登录接口有独立限流兜底。
- 代价与收益都要落在「零第三方依赖 + 授权零风险 + 可升级」这三点上。
