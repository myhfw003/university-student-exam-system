| 里程碑 | 位置 | 标志 | 可交付物 |

```
关键路径：P0 → P2 → P3 → P4 → P6 → P9

并行安排：
  P0 期间：前端设计令牌与基础组件（不依赖后端）
  P1 期间：前端登录页与路由骨架（用 MSW 打桩）
```

**接口契约先行**：`05-api.md` 在 P0 结束前冻结并产出 OpenAPI 基线，此后前端用 MSW 按契约打桩，前后端并行推进。

## 4. 每阶段的验收仪式

每个阶段结束执行一次**可运行验收**，不是看代码，是跑场景：

| 阶段 | 验收脚本 |
|---|---|
| P0 | `docker compose up -d` → `/health/ready` 200 → 登录拿 Token → 访问 `/auth/me` 成功 → CI 跑通 |
| P1 | 管理端建 5 个组织标签 → 导入 50 名学生 CSV → 给学生分配角色 → 审计页看到操作记录 |
| P2 | 导入一份 30 题 CSV → 预览标红 2 行 → 采纳 → 批量发布 → 题库工作台筛选"较难 + 计算机网络" |
| P3 | 配置规则（领域 + 难度配比 + 目标 100 分）→ 生成 → 故意缩小池量验证报错 → 调整后生成 → 微调 → 发布 → 快照校验 |
| P4 | 起 1000 VU 压测 → 中途刷新页面 → 断网 30 秒 → 恢复 → 交卷 → 对账校验丢答率为 0 |
| P5 | 考试中切屏 3 次 → 被强制交卷 → 教师大屏实时显示该考生 → 教师发警告 → 考生端弹出 |
| P6 | 交卷后阅卷队列出现主观题 → 给分写评语 → 改分产生流水 → 发布成绩 → 学生端可见 |
| P7 | 制造错题 → 错题本出现 → 单题重做正确 → 错题本移除 → 能力画像更新 |
| P8 | 练习提交 3 次后第 4 次被拒 → 即时反馈模式显示解析 → 错题回流 |
| P9 | 全量压测达标 → 恢复演练 → 安全清单 15 项 → 生产部署冒烟 |

## 5. 风险登记册

| 编号 | 风险 | 概率 | 影响 | 缓解 | 触发信号 |
|---|---|---|---|---|---|
| R-01 | 1000 并发下作答链路延迟超标 | 中 | 高 | 原生 upsert + PgBouncer + 快照缓存 + 限流；P0 即建压测基线 | 压测 p95 > 500 ms |
| R-02 | 离线队列与服务器产生顺序冲突 | 中 | 高 | `clientSeq` 单调 + 服务端幂等 + 对账作业；RTO 明确 | 对账发现差异 |
| R-03 | 抽题规则引擎在真实题库上表现不佳（池量总是不足） | 高 | 中 | 规则支持"至少 N 题"的软配额 + 缺口可视化；种子数据充足 | 频繁出现 23101 |
| R-04 | 前端与后端契约漂移 | 中 | 中 | 契约先行 + OpenAPI 差异检查 + 契约测试 | CI 契约检查失败 |
| R-05 | 防作弊被绕过（改前端代码） | 高 | 中 | 诚实声明能力边界；强化服务端计时与追溯；异常行为统计 | 监考发现异常模式 |
| R-06 | 主观题初判准确率低导致阅卷负担 | 中 | 中 | 关键词命中可视化供教师快速确认；支持批量采纳 | 阅卷耗时超预期 |
| R-07 | EF 迁移在生产大表上锁表 | 中 | 高 | 迁移分两步；`CREATE INDEX CONCURRENTLY`；避开考试窗口 | 迁移耗时超阈值 |
| R-08 | 监考推送在 1000 人时挤占作答资源 | 低 | 高 | 2 秒批量聚合 + 独立 Redis 连接 + 推送失败降级 | 作答 p95 在监考开启时上升 |
| R-09 | 需求变更导致已开发模块返工 | 中 | 中 | 设计文档先行冻结；变更走 ADR；接口契约冻结 | 阶段内需求变更 |
| R-10 | 依赖库授权变更（如 MediatR 转商业） | 低 | 中 | 锁定版本 + 新增依赖前查授权 | 依赖发布新版本 |
| R-11 | 单人开发导致关键模块无评审 | 中 | 中 | 架构测试 + 覆盖率门禁 + 自评审清单；关键阶段找外部评审 | — |

## 6. 技术预研项（不占用主线时间）

以下在 P0 期间的空闲时间做小型验证（每个 ≤ 1 天），目的是**尽早暴露风险**而不是提前实现功能：

| 编号 | 预研内容 | 验证目标 | 若失败的备选 |
|---|---|---|---|
| SP-01 | PgBouncer 事务池 + EF Core | 确认 `UseServerPreparedStatements=false` 下无异常，吞吐达标 | 改用 PgBouncer session 池；或直连 PG + 调大 `max_connections` |
| SP-02 | 原生批量 upsert 的实际吞吐 | 确认 1000 QPS 下 PG 不成为瓶颈 | 分区表 + 批量 COPY；或引入写入缓冲 |
| SP-03 | SignalR 1000 连接 + Redis Backplane | 确认 2 秒批量推送的延迟与资源占用 | 降级为 5 秒一批；或改用 SSE |
| SP-04 | Dexie 队列在 1000 题规模下的读写性能 | 确认 IndexedDB 不成为瓶颈 | 队列只存差异（而非全量快照）；或改用 OPFS |
| SP-05 | 递归 CTE 标签树在 10 万标签下的表现 | 确认查询延迟可接受 | 物化路径 + 定期物化缓存 |
| SP-06 | XLSX 解析在 5 万行文件下的内存占用 | 确认不 OOM | 流式读取；或限制 1 万行 |

**预研的产出是结论与决策**，不是代码。结论写进 ADR。

## 9. 下一步

**设计文档已确认，P0 已启动。** 从 T-P0-01 开始。

确认时确定的事项（与文档一致，可直接作为实现依据）：

| # | 事项 | 结论 |
|---|---|---|
| 1 | 组卷方式 | **支持一键出卷**：标签规则自动抽题（确定性种子）+ 手工微调；题池不足明确报错，不静默降级 |
| 2 | 防作弊对外口径 | **按诚实标注能力边界**：「可审计 + 可威慑」，非绝对防护；产品文案与手册不得写"杜绝作弊" |
| 3 | 登录与用户范围 | **账号 + 密码**，账号不限定学号，**支持社会人士使用**；在校学生可用学号作为账号 |
| 4 | 组织建模 | 不建组织树，用**组织维度标签**（学院 → 专业 → 班级）表达；组织维度只挂用户，题目只挂前四维 |
| 5 | 其余技术设计 | 五维标签划分、答案可靠性方案、认证方案、1000 并发阈值、数据库分 Schema 与权限收回、阶段划分与 76 人日粗估 —— 均按文档执行 |

因第 3 条产生的连带修订（已回灌全部文档）：

- 账号规则：4..32 位，字母/数字/下划线/点/中划线，大小写不敏感唯一；数据库加 CHECK 约束。
- 组织标签对用户**可选**，社会人士不挂任何组织标签。
- 新增角色 `general_user`（社会人士），权限与在校学生一致。
- 考试名单支持三种纳入方式：按组织标签 / 指定考生 / 全员开放。
- 名单导入 CSV 的院系/专业/班级三列可空，为空即视为社会人士。
- 水印与监考表格中的"学号"改为"账号"。
